## 這版修的是「卡片從來沒有出現」的真正原因

你之前看到 `Custom element doesn't exist: custom:taipower-bill-card`，不是卡片寫錯，是**載入卡片的網址天生不能用**。

`raw.githubusercontent.com` 回傳的檔頭是：

```
content-type: text/plain; charset=utf-8
x-content-type-options: nosniff
```

瀏覽器看到 `nosniff` 就**拒絕把這個檔案當 JavaScript 模組執行**，所以 `customElements.define()` 這行永遠不會跑，Lovelace 就回報「自訂元素不存在」。這是 GitHub raw 的固定行為，**換瀏覽器、清快取、改 URL 大小寫都不會好**。

v0.2.3 把卡片放進整合自己的 `custom_components/taipower_bill/www/`，改由 **Home Assistant 自己以同源伺服**。HA 自己的靜態處理程式回傳的是 `text/javascript`（已在 2026.10 實機驗證），這樣 `res_type: module` 才會真的載入。

## 安裝／更新步驟（請照這個做）

### A. 用 HACS 更新（已裝過的人）

1. HACS → 整合結構 → **Taipower Bill (台電電費)** → 更新到 `0.2.3`
2. **重新啟動 Home Assistant**（一定要重啟，`www/` 的靜態路由是啟動時註冊的）
3. 左側 **設定 → 儀表板 → 自訂資源**，把舊的那筆 `https://raw.githubusercontent.com/...` **刪掉**
4. 新增一筆自訂資源：
   - **URL**：`/taipower-bill-card.js`
   - **類型**：**JavaScript 模組**（JavaScript module）
5. 重新整理瀏覽器（用戶端 → 重新載入），開 `http://192.168.31.252:8123/taipower-bill`

> 不用再手動複製任何檔案。URL 就是 `/taipower-bill-card.js`，前面不用加 IP、不用加 `hacsfiles`。

### B. 驗證它真的有伺服（可用終端機）

```bash
# 應該要看到 text/javascript；如果是 text/plain 就代表還沒重啟或路徑不對
curl -sSI http://192.168.31.252:8123/taipower-bill-card.js | grep -i content-type
```

看到 `content-type: text/javascript` 就對了。

### C. 第一次安裝（新機器）

1. HACS → 整合結構 → ⋮ → 自訂儲存庫 → 輸入 `kingwap99/ha-taipower-bill`，類別選 **整合結構**
2. 安裝 **Taipower Bill (台電電費)**，重啟 HA
3. 設定 → 裝置與服務 → 新增整合 → 搜尋 **Taipower Bill**，一戶一組（兩戶就建兩個）
4. 照上面 A 的 3–5 步加上自訂資源與頁面

## 同時修好的兩件事

**1. 戶別名稱顯示成 `no17` 這種內部代號**
卡片之前優先取實體屬性裡的戶名（整合內部存的 `no17`），所以你在設定裡打「17 號」也不會照你的寫法顯示。現在改成**以卡片自己的 label 為準**，屬性代號只做退回用。

**2. 週期剛開始時「推估電費」看起來像 bug**
10 月才過 3 天就推估出一張一千多塊的帳單（實際是五千到七千），那是把 3 天的用電硬乘 63 天的結果。現在資料不足 7 天时顯示「推估資料不足（僅 N 天）」，**不印那個會誤導人的數字**；满 7 天後推估才會出現。

## 給開發者：測試怎麼鎖住這個修法

新增 `tests/ha/test_real_static_card.py`（3 項）：

- 卡片檔案必須在 `custom_components/taipower_bill/www/` 裡面（HACS 只複製這個目錄，放外面等於根本沒裝到卡片）
- `async_setup` 必須在 `/taipower-bill-card.js` 這個**同源**網址註冊，且 `cache_headers=False`（否則 HACS 升級後會被一年的快取釘死在舊卡片）
- `hass.http` 不存在時（無 headless 環境）整合仍要能啟動，只警告不崩潰

已做變異測試確認斷言真的會咬：把 `CARD_URL` 換回 GitHub raw 網址 → 失敗；把 `cache_headers` 改成 `True` → 失敗。

`tests/ha` 實機測試 **35 passed**、卡片渲染檢查 **32 passed**。
（離線 `pytest` 在此沙箱對 HA 2026.10 壞掉（`homeassistant.util.logging`，在純 HEAD 上也一樣報錯），所以以 `tests/ha` 為準。）
